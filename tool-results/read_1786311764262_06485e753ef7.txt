    49→### 3. How Are Rules Represented in C++?
    50→
    51→Stockfish 11 does **not** store rules as text strings. It uses **Bitboard math** and **Packed Middlegame/Endgame Scores**.
    52→
    53→Every rule outputs a **`Score` pair**: $S(\text{Middlegame}, \text{Endgame})$.
    54→
    55→```cpp
    56→// Stockfish 11's internal score representation (32-bit packed integer)
    57→// Lower 16 bits = Middlegame value (cp)
    58→// Upper 16 bits = Endgame value (cp)
    59→Score S(int mg, int eg);
    60→```
    61→
    62→#### Example: How Stockfish 11 calculates a Knight Outpost
    63→Inside `evaluate.cpp`, Stockfish 11 checks if a Knight is on an outpost using a single line of bitboard math:
    64→
    65→```cpp
    66→// If Knight is on an outpost supported by a pawn, and no enemy pawn can attack it:
    67→if (outpost & knight_bitboard) {
    68→    score += OutpostBonus[KNIGHT][square]; // e.g., S(32, 22) -> +32cp in MG, +22cp in EG
    69→}
    70→```
    71→
    72→Then, at the end of evaluation, it interpolates MG and EG based on the game phase:
    73→
    74→$$\text{Final Eval} = \frac{\text{MG\_Score} \times \text{Phase} + \text{EG\_Score} \times (128 - \text{Phase})}{128}$$

   860→
   861→### 6.1 Subprocess & UCI Lifecycle Management
   862→Stockfish must run as a persistent background subprocess communicated with over stdin/stdout via UCI protocol. **DO NOT** launch a new process for every move.
   863→
   864→### 6.2 Engine Parameter Requirements
   865→- `Threads`: $\min(4, \text{system\_cores} - 1)$
   866→- `Hash`: $512 \text{ MB}$ minimum ($1024 \text{ MB}$ recommended)
   867→- `MultiPV`: $3$ (Always analyze top 3 lines to discover alternative moves)
   868→- `Contempt`: $0$ (Must be strictly neutral)
   869→- `Ponder`: `false`
   870→
   871→### 6.3 MATE Normalization & Evaluation Parsing Algorithm
   872→
   873→```
   874→FUNCTION parse_stockfish_score(uci_score_obj, current_ply):
   875→    IF uci_score_obj.is_mate():
   876→        moves_to_mate = uci_score_obj.mate()
   877→        IF moves_to_mate > 0:
   878→            normalized_cp = 10000 - (moves_to_mate * 10) - current_ply
   879→        ELSE:
   880→            normalized_cp = -10000 - (moves_to_mate * 10) + current_ply
   881→        RETURN StockfishEvalModel(
   882→            eval_type="mate",
   883→            value=moves_to_mate,
   884→            normalized_cp=normalized_cp,
   885→            win_chance=1.0 IF moves_to_mate > 0 ELSE 0.0
   886→        )
   887→    ELSE:
   888→        cp_val = uci_score_obj.score()
   889→        # Win chance formula based on lichess/Stockfish centipawn conversion
   890→        win_chance = 1 / (1 + 10 ** (-cp_val / 400.0))
   891→        RETURN StockfishEvalModel(
   892→            eval_type="cp",
   893→            value=cp_val,
   894→            normalized_cp=cp_val,
   895→            win_chance=win_chance
   896→        )
   897→
   898→FUNCTION analyze_position(board, depth=20, multipv=3):
   899→    SEND UCI command: "position fen " + board.fen()
   900→    SEND UCI command: "go depth " + depth
   901→    
   902→    WHILE subprocess output NOT contains "bestmove":
   903→        READ line
   904→        IF line contains "info depth" AND line contains "multipv":

   906→

   909→```

   913→## 7. LAYER 2: SYMBOLIC FEATURE & THREAT EXTRACTOR
   914→
   915→This module is the core truth engine for tactics and positional features. It must be 100% deterministic using `python-chess`.
   916→
   917→### 7.1 Static Exchange Evaluation (SEE) Algorithm
   918→The system must calculate `SEE` for captures to determine if an exchange is winning, equal, or a material blunder.
   919→
   920→```
   921→FUNCTION calculate_see(board, move):
   922→    # Uses python-chess built-in board.see(move)
   923→    # Returns net material gain in centipawns
   924→    see_value = board.see(move)
   925→    is_winning_capture = (see_value >= 0)
   926→    RETURN see_value, is_winning_capture
   927→```
   928→
   929→### 7.2 Null-Move Threat Detection Algorithm
   930→To find exact, concrete threats created by a move $M$, the extractor must play $M$, execute a Null-Move (pass turn), and check what winning captures exist.
   931→
   932→```
   933→FUNCTION detect_concrete_threats(board_before, move):
   934→    board = board_before.copy()
   935→    board.push(move)  # Play the move
   936→    
   937→    threats_list = []
   938→    
   939→    # Null Move is illegal if player is in check
   940→    IF board.is_check():
   941→        RETURN threats_list
   942→        
   943→    board.push(chess.Move.null())  # Pass the opponent's turn
   944→    
   945→    FOR EACH legal_move IN board.legal_moves:
   946→        IF board.is_capture(legal_move):
   947→            see_value = board.see(legal_move)
   948→            IF see_value >= 0:  # Only count winning/equal threats
   949→                target_sq = legal_move.to_square
   950→                target_piece = board.piece_at(target_sq)
   951→                IF target_piece IS NOT NONE:
   952→                    threats_list.append(ConcreteThreatModel(
   953→                        threat_move_san = board.san(legal_move),
   954→                        threat_move_uci = legal_move.uci(),
   955→                        target_piece = target_piece.piece_type,
   956→                        target_square = square_name(target_sq),
   957→                        net_gain_cp = see_value,
   958→                        is_winning_capture = (see_value > 0)
   959→                    ))
   960→                    
   961→    board.pop()  # Pop null move
   962→    board.pop()  # Pop player move
   963→    
   964→    # Deduplicate threats by target square, keep highest gain
   965→    DEDUPLICATE threats_list BY target_square KEEP MAX net_gain_cp
   966→    RETURN threats_list
   967→```
   968→
   969→### 7.3 Outpost Detection Algorithm
   970→A square $S$ is an **Outpost** if:
   971→1. $S$ is on Rank 4, 5, or 6 (for White) or Rank 3, 4, or 5 (for Black).
   972→2. $S$ is defended by a friendly Pawn.
   973→3. $S$ cannot be attacked by an enemy Pawn now or on adjacent files in the future.
   974→
   975→```
   976→FUNCTION is_outpost_square(board, square, color):
   977→    rank = square_rank(square)
   978→    file = square_file(square)
   979→    
   980→    # Rank Restrictions
   981→    IF color == WHITE AND rank NOT IN [3, 4, 5]: RETURN False  # 0-indexed: 3=Rank 4
   982→    IF color == BLACK AND rank NOT IN [2, 3, 4]: RETURN False  # 0-indexed: 4=Rank 5
   983→    
   984→    # Check friendly pawn support
   985→    pawn_attackers = board.attackers(color, square)
   986→    has_pawn_support = ANY(board.piece_at(sq).piece_type == PAWN FOR sq IN pawn_attackers)
   987→    IF NOT has_pawn_support: RETURN False
   988→    
   989→    # Check enemy pawn attack potential (current or future)
   990→    enemy_color = NOT color
   991→    adjacent_files = [file - 1, file + 1] FILTERED BY valid_files (0..7)
   992→    enemy_pawns = board.pieces(PAWN, enemy_color)
   993→    
   994→    FOR sq IN enemy_pawns:
   995→        IF square_file(sq) IN adjacent_files:
   996→            e_rank = square_rank(sq)
   997→            IF color == WHITE AND e_rank >= rank: RETURN False  # Pawn can attack or passed
   998→            IF color == BLACK AND e_rank <= rank: RETURN False
   999→            
  1000→    RETURN True
  1001→```
  1002→
  1003→### 7.4 Center Control & Open File Algorithms
  1004→- **Center Control Delta:** Calculate total attacks on $d4, d5, e4, e5$ by `board.is_attacked_by(color, square)` before and after the move.
  1005→- **Open File Control:** A file is **Open** if it contains 0 Pawns of either color. A file is **Semi-Open** if it contains 0 friendly Pawns and $\ge 1$ enemy Pawn.

  1009→## 8. LAYER 3: GAME MEMORY STACK & NARRATIVE STATE TRACKER
  1010→
  1011→### 8.1 Purpose & State Preservation
  1012→The Game Memory Stack accumulates narrative state move-by-move. It prevents the system from evaluating moves in isolation, allowing explanations to reference past sacrifices, ongoing pawn weaknesses, and recent momentum.
  1013→
  1014→### 8.2 State Update Algorithm
  1015→
  1016→```
  1017→CLASS GameMemoryStack:
  1018→    FUNCTION __init__():
  1019→        self.persistent_imbalances = SET()
  1020→        self.key_past_events = LIST()
  1021→        self.recent_moves_fifo = QUEUE(max_size=3)
  1022→
  1023→    FUNCTION process_ply(ply_index, move_san, fen_before, fen_after, eval_delta_cp, see_score, move_analysis):
  1024→        # 1. Update Recent Moves Buffer
  1025→        self.recent_moves_fifo.append(move_san)
  1026→        
  1027→        # 2. Detect Sacrifice Event
  1028→        IF move_analysis.is_capture AND see_score < -150 AND eval_delta_cp > -50:
  1029→            self.key_past_events.append(HistoricEventModel(
  1030→                move_number = (ply_index // 2) + 1,
  1031→                ply = ply_index,
  1032→                player_color = board.turn,
  1033→                move_san = move_san,
  1034→                event_type = "material_sacrifice",
  1035→                description = f"Sacrificed {move_analysis.captured_piece} on {move_san}",
  1036→                eval_delta_cp = eval_delta_cp
  1037→            ))
  1038→
  1039→        # 3. Detect Major Eval Spike (|eval_delta| >= 100cp)
  1040→        ELSE IF ABS(eval_delta_cp) >= 100:
  1041→            self.key_past_events.append(HistoricEventModel(
  1042→                move_number = (ply_index // 2) + 1,
  1043→                ply = ply_index,
  1044→                player_color = board.turn,
  1045→                move_san = move_san,
  1046→                event_type = "major_eval_spike",
  1047→                description = f"Evaluation shifted by {eval_delta_cp}cp after {move_san}",
  1048→                eval_delta_cp = eval_delta_cp
  1049→            ))
  1050→
  1051→        # 4. Update Persistent Imbalances
  1052→        UPDATE_IMBALANCES(self.persistent_imbalances, fen_after)
  1053→```

  1231→## 13. ERROR HANDLING, EDGE CASES & FAILURE MODES
  1232→
  1233→### 13.1 Edge Case Catalog & Handling Mandates
  1234→
  1235→1. **In-Check Null-Move Prohibition:**
  1236→   * *Scenario:* Player is in check. Executing `chess.Move.null()` raises `ValueError` in `python-chess`.
  1237→   * *Mandate:* Layer 2 MUST check `if board.is_check():` before attempting Null-Move threat detection. If in check, return empty concrete threats list or evaluate check escapes explicitly.
  1238→2. **Terminal Game States (Checkmate / Stalemate):**
  1239→   * *Scenario:* Move produces Checkmate or Stalemate. Stockfish score returns `mate 0` or `cp 0`.
  1240→   * *Mandate:* Skip Null-Move analysis. Set `eval_type="mate"`, `value=0`. Inject explicit `is_checkmate=True` / `is_stalemate=True` flag into Layer 4 payload.
  1241→3. **Underpromotions (e.g., Pawn to Knight/Rook/Bishop):**
  1242→   * *Scenario:* Move is `e7e8n`.
  1243→   * *Mandate:* Layer 2 must explicitly record promotion piece type and evaluate if promotion created a fork or knight check.
  1244→4. **Stockfish Subprocess Crash / Timeout:**
  1245→   * *Scenario:* Engine crashes or freezes due to memory exhaustion.
  1246→   * *Mandate:* Subprocess wrapper must implement a 5-second hard timeout per command. If process dies, auto-restart process, flush buffer, and retry query once. If second failure, throw `EngineDeadlockException`.
  1247→5. **LLM API Rate Limiting / 5xx Errors:**
  1248→   * *Scenario:* OpenAI/Anthropic API returns HTTP 429 or 503.
  1249→   * *Mandate:* Implement exponential backoff with jitter (retries: 4, backoff factors: 1s, 2s, 4s, 8s). If all retries fail, fallback to a local deterministic template-based explanation generator (`FallbackTemplateEngine`).
