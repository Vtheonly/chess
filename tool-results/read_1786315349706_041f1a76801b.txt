   216→## 4. MOVE CLASSIFICATION & ACCURACY ALGORITHMS
   217→
   218→### 4.1 Win Chance Conversion Formula
   219→To calculate move accuracy and classification fairly across all phases of the game, raw centipawn evaluations must be converted to a **Win Chance Probability** $W \in [0.0, 1.0]$ using the Lichess/Stockfish sigmoid formula:
   220→
   221→$$W = \frac{1}{1 + 10^{-\text{cp} / 400.0}}$$
   222→
   223→If the evaluation is a mate score:
   224→* $\text{Mate in } +N \implies W = 1.0 - (N \times 0.01)$
   225→* $\text{Mate in } -N \implies W = 0.0 + (N \times 0.01)$
   226→
   227→### 4.2 Move Classification Algorithm
   228→For a move played at ply $P$, calculate $\Delta W = W_{\text{after}} - W_{\text{before}}$ (from the perspective of the player making the move).
   229→
   230→```
   231→FUNCTION classify_move(board_before, played_move, best_move, eval_before, eval_after, see_score):
   232→    W_before = win_chance(eval_before)
   233→    W_after = win_chance(eval_after)
   234→    delta_W = W_after - W_before  # Negative value represents accuracy drop
   235→
   236→    # 1. Check for BEST or BOOK
   237→    IF played_move == best_move:
   238→        RETURN "BEST"
   239→        
   240→    # 2. Check for BRILLIANT
   241→    # Definition: Material sacrifice (SEE < -150) that is either the best move 
   242→    # or maintains win chance within 3% of best move.
   243→    IF is_sacrifice(board_before, played_move) AND see_score < -150 AND delta_W >= -0.03:
   244→        RETURN "BRILLIANT"
   245→        
   246→    # 3. Check for GREAT
   247→    # Definition: The ONLY move that preserves a winning/equal position when all other moves lose >20% win chance.
   248→    IF is_only_viable_move(board_before, played_move, second_best_delta_W) AND delta_W >= -0.02:
   249→        RETURN "GREAT"
   250→
   251→    # 4. Standard Win Chance Drop Classifications
   252→    IF delta_W >= -0.02:
   253→        RETURN "EXCELLENT"
   254→    ELSE IF delta_W >= -0.05:
   255→        RETURN "GOOD"
   256→    ELSE IF delta_W >= -0.10:
   257→        RETURN "INACCURACY"
   258→    ELSE IF delta_W >= -0.20:
   259→        RETURN "MISTAKE"
   260→    ELSE:
   261→        # Check if a winning tactic was completely missed
   262→        IF W_before >= 0.70 AND W_after < 0.50:
   263→            RETURN "MISS"
   264→        RETURN "BLUNDER"
   265→```
   266→
   267→### 4.3 Game Accuracy Percentage Formula
   268→For a game with $N$ moves played by a player, calculate move accuracy percentage $A$ as:
   269→
   270→$$A = 100 \times \frac{1}{N} \sum_{i=1}^{N} \left( 1.031668 \times e^{-0.04354 \times (\Delta W_i \times 100)^2} - 0.031668 \right)$$

   274→## 5. MODE A: INTERACTIVE HUMAN VS AI (COACHED PLAY)
   275→
   276→### 5.1 Workflow & Execution Loop
   277→1. Player sets **Player Color** (White/Black), **AI Play Elo** (800–2800), and **Coach Elo** (800, 1200, 1500, 1800+).
   278→2. If Player is Black, engine immediately executes first move as White.
   279→3. Player selects square $\rightarrow$ Frontend highlights legal move target squares.
   280→4. Player executes drag-and-drop or click-click move $\rightarrow$ Frontend optimistically plays move, triggers audio, and requests backend validation.
   281→5. Backend verifies move legality, updates Stockfish analysis, extracts Layer 2 symbolic deltas, updates Layer 3 memory stack, calls Layer 5 LLM Narrator, and streams response back over WebSocket.
   282→6. Frontend updates Board, Eval Bar, Move Table, and Narrative Panel simultaneously.
   283→7. Backend triggers Stockfish to compute AI's counter-move (scaled to selected AI Play Elo via Stockfish UCI limit parameters `UCI_LimitStrength` and `UCI_Elo`).
   284→8. AI move is executed on board $\rightarrow$ Audio plays $\rightarrow$ AI move analysis streams in.
   285→
   286→### 5.2 Stockfish Elo Scaling Execution
   287→To restrict Stockfish's playing strength for human play, the backend UCI process must be configured per move:
   288→
   289→```python
   290→# Stockfish UCI Strength Reduction Protocol
   291→def configure_engine_elo(engine_process, play_elo: int):
   292→    if play_elo >= 2800:
   293→        engine_process.send_command("setoption name UCI_LimitStrength value false")
   294→    else:
   295→        engine_process.send_command("setoption name UCI_LimitStrength value true")
   296→        engine_process.send_command(f"setoption name UCI_Elo value {play_elo}")
   297→```

   301→## 6. MODE B: AI VS AI (SELF-PLAY SIMULATION)
   302→
   303→### 6.1 Workflow & Simulation Engine
   304→1. User configures **White AI Elo** (e.g., 1000) and **Black AI Elo** (e.g., 2200).
   305→2. User sets **Auto-Play Interval** (500ms to 5000ms).
   306→3. User clicks **"Start Simulation"**.
   307→4. Loop executes over WebSocket:
   308→   * Backend requests Stockfish move for White (at White Elo).
   309→   * Move executed $\rightarrow$ Full analysis + Layer 2 Deltas + Layer 5 Narrative generated.
   310→   * Frame broadcast to client $\rightarrow$ Client animates move, updates eval bar, appends narrative.
   311→   * Delay `autoPlaySpeedMs`.
   312→   * Backend requests Stockfish move for Black (at Black Elo).
   313→   * Repeat until Checkmate, Stalemate, or 3-fold repetition.
   314→5. User can click **Pause**, **Step Forward**, **Step Backward**, or **Modify Elo Mid-Game**.

   634→### 2. DETAILED PROVIDER ADAPTER IMPLEMENTATIONS
   635→
   636→#### 2.1 Groq Adapter Implementation
   637→- **SDK Usage:** `from groq import AsyncGroq`
   638→- **Request Parameters:** `temperature=0.2`, `response_format={"type": "json_object"}`, `max_tokens=400`.
   639→- **Special Handling:** Groq requires strict system prompt enforcement to output valid JSON.
   640→
   641→```python
   642→# Groq Adapter Logic
   643→CLASS GroqAdapter(BaseLLMAdapter):
   644→    ASYNC FUNCTION generate_narrative(payload, system_prompt, api_key, model_name):
   645→        client = AsyncGroq(api_key=api_key)
   646→        
   647→        response = AWAIT client.chat.completions.create(
   648→            model=model_name,
   649→            messages=[
   650→                {"role": "system", "content": system_prompt + "\nOUTPUT MUST BE VALID JSON MATCHING SCHEMA."},
   651→                {"role": "user", "content": payload.model_dump_json()}
   652→            ],
   653→            temperature=0.2,
   654→            max_tokens=400,
   655→            response_format={"type": "json_object"}
   656→        )
   657→        
   658→        raw_json = response.choices[0].message.content
   659→        RETURN PARSE_AND_VALIDATE_JSON(raw_json)
   660→```
   661→
   662→#### 2.2 OpenRouter Adapter Implementation
   663→- **HTTP Endpoint:** `POST https://openrouter.ai/api/v1/chat/completions`
   664→- **Headers Required:**
   665→  - `Authorization: Bearer <OPENROUTER_API_KEY>`
   666→  - `HTTP-Referer: https://caissaxai.com` (App identification)
   667→  - `X-Title: CaissaXAI Chess Engine`
   668→
   669→```python
   670→# OpenRouter Adapter Logic
   671→CLASS OpenRouterAdapter(BaseLLMAdapter):
   672→    ASYNC FUNCTION generate_narrative(payload, system_prompt, api_key, model_name):
   673→        headers = {
   674→            "Authorization": f"Bearer {api_key}",
   675→            "HTTP-Referer": "https://caissaxai.com",
   676→            "X-Title": "CaissaXAI",
   677→            "Content-Type": "application/json"
   678→        }
   679→        
   680→        body = {
   681→            "model": model_name, # e.g. "anthropic/claude-3.5-sonnet"
   682→            "messages": [
   683→                {"role": "system", "content": system_prompt},
   684→                {"role": "user", "content": payload.model_dump_json()}
   685→            ],
   686→            "temperature": 0.2,
   687→            "response_format": {"type": "json_object"}
   688→        }
   689→        
   690→        response = AWAIT httpx_post("https://openrouter.ai/api/v1/chat/completions", headers=headers, json=body)
   691→        raw_json = response.json()["choices"][0]["message"]["content"]
   692→        RETURN PARSE_AND_VALIDATE_JSON(raw_json)
   693→```
   694→
   695→#### 2.3 Google AI Studio (Gemini) Adapter Implementation
   696→- **SDK Usage:** `google.genai` SDK or Direct REST API (`v1beta`)
   697→- **Endpoint:** `POST https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent?key={API_KEY}`
   698→- **Structured Output Config:** `response_mime_type="application/json"`
   699→
   700→```python
   701→# Google AI Studio (Gemini) Adapter Logic
   702→CLASS GoogleGeminiAdapter(BaseLLMAdapter):
   703→    ASYNC FUNCTION generate_narrative(payload, system_prompt, api_key, model_name):
   704→        # Configure Gemini Client
   705→        url = f"https://generativelanguage.googleapis.com/v1beta/models/{model_name}:generateContent?key={api_key}"
   706→        
   707→        body = {
   708→            "contents": [{
   709→                "parts": [
   710→                    {"text": system_prompt + "\n\nJSON PAYLOAD:\n" + payload.model_dump_json()}
   711→                ]
   712→            }],
   713→            "generationConfig": {
   714→                "temperature": 0.2,
   715→                "responseMimeType": "application/json"
   716→            }
   717→        }
   718→        
   719→        response = AWAIT httpx_post(url, json=body)
   720→        raw_json = response.json()["candidates"][0]["content"]["parts"][0]["text"]
   721→        RETURN PARSE_AND_VALIDATE_JSON(raw_json)
   722→```
